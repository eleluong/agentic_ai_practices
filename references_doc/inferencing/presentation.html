The Core Thesis

Inference is two distinct workloads

Prefill

Processes the entire prompt in one parallel pass. Large matrix-matrix products saturate tensor cores.

  • Compute-bound
  • High arithmetic intensity
  • Drives TTFT (time-to-first-token)

Decode

Emits one token at a time, re-reading all weights and the KV cache each step.

  • Memory-bandwidth-bound
  • Low arithmetic intensity
  • Drives TPOT / inter-token latency
Consequence: Weight-only quantization speeds up decode; native low-bit GEMMs unlock prefill. Batch size moves you between the two regimes.

Section 2

The Roofline Model

Below the ridge

Performance is limited by bytes/sec moved. Adding compute does nothing — you need better memory efficiency.

Above the ridge

Tensor cores saturate. Now FLOPs are the constraint; low-precision GEMMs help.

Batch is the lever

Intensity ≈ batch size. Small batches sit in the bandwidth-bound region of decode.

Section 3

KV Cache & state management

PagedAttention

KV stored in fixed-size blocks with a block table — like OS virtual memory. Eliminates internal fragmentation.

RadixAttention

Prefixes cached in a radix tree so shared system prompts and few-shot examples reuse KV across requests.

MLA

Compresses KV into a low-rank latent vector (512 + 64 RoPE dims), shrinking the cache dramatically.

Section 3

Multi-head Latent Attention

Standard multi-head attention caches a K and V vector per head per token. MLA instead caches a single compressed latent and reconstructs K/V on the fly.

Latent dims 512 + 64 RoPE
Cache reduction > 90%

Used by DeepSeek-V2/V3 to trade a little recompute for a much smaller decode-time working set.

RoPE scaling

  • Linear — scale m → m/α; cheap but blurs local syntax.
  • NTK-Aware — rescale the base, interpolating low frequencies only.
  • YaRN — three regimes + attention temperature; best 128K+ stability.

Sparse KV eviction

  • StreamingLLM — 4 attention sinks + rolling window, O(W) forever.
  • H2O — keep recent + "heavy hitters", evict up to 80% of KV.
  • SnapKV — select critical prompt clusters before decode begins.

Ring Attention shards the sequence across GPUs, scaling context with device count — but eviction methods are lossy by design.

Decoding & sampling strategies

Strategy Logic Hyperparam Use case
Greedy argmax z_i T = 0 Code, math, deterministic APIs
Temperature z_i / T T ∈ [0.1, 2.0] Global randomness vs determinism
Top-k keep top-k logits k ∈ [20, 100] Coarse tail cutoff
Top-p (nucleus) cumulative sum ≥ p p ∈ [0.8, 0.95] Adaptive set by entropy
Min-p p_i ≥ p_min · p_max p_min ∈ [0.05, 0.1] High-coherence reasoning & dialogue
Beam Search maintain B hypotheses B ∈ [2, 8] Translation, short extraction

Min-p scales the cutoff with model confidence — entropy steps keep candidates, confident steps prune hard.

Section 5

Backends & kernels

FlashAttention 2 / 3 / 4

Tiles the attention computation to keep it in SRAM, avoiding materializing the full N×N matrix in HBM.

FlashInfer

Kernel library of paged and fused attention primitives tuned for decoding workloads.

Online Softmax

Streaming softmax that rescales accumulators as blocks arrive — the trick behind memory-efficient attention.

// online softmax recurrence

m = max(m, block_max)

l = l · exp(m_old − m) + Σ exp(x − m)

acc = acc · exp(m_old − m) + Σ exp(x − m) · v

out = acc / l

Section 6

Disaggregation & Chunked Prefill

Co-located

Prefill and decode share the same GPU. Long prefill stalls in-flight decodes — token jitter.

Chunked prefill

Splits prefill into ~2048-token blocks interleaved with decode steps — local, no extra hardware.

P/D Disaggregated

Separate GPU pools for prefill & decode. TTFT and ITL tuned independently. 2.4× goodput on MI300X.

Render Tier

GPU-less /render + /derender move tokenization & parsing off the GPU box. Engine runs token→token only.

Goodput — not peak throughput — is the metric: the request rate sustainable while all requests meet both TTFT & ITL targets. P/D requires RDMA/NVLink; verify GPU peer-to-peer before benchmarking. All three splits are orthogonal and combinable.

Section 6

Quantization for inference

Method Bits When it wins
AWQ W4A16 Low-batch decode bound by weight transfer
GPTQ W4A16 Broad compatibility, single-GPU deployment
FP8 W8A8 High-batch compute-bound prefill on Hopper+
NVFP4 W4A4 Blackwell native 4-bit tensor cores
Low batch → weight-only W4A16 gives direct decode speedups (fewer bytes read per token).
High batch → needs native low-bit GEMMs like FP8 / NVFP4; dequant overhead otherwise cancels the gain.

Section 6

Speculative decoding

Draft & verify

A small model proposes k tokens; the target model scores them in a single forward pass.

Lossless

Rejected tokens fall back to the target's own distribution — output is identical in expectation.

Variants

Classic draft model, Medusa heads, EAGLE-2 feature drafters, and MTP multi-token prediction.

speedup ≈ accepted_tokens_per_pass ÷ verify_cost

Section 6

Diffusion LLMs

Instead of left-to-right token generation, diffusion language models start from noise and iteratively denoise the whole sequence in parallel — refining confident positions while re-sampling uncertain ones.

// iterative denoising

  1. 1. Initialize all positions as masked / noisy.
  2. 2. Predict every token in parallel.
  3. 3. Lock in low-entropy (high-confidence) tokens.
  4. 4. Re-noised uncertain positions remain.
  5. 5. Repeat for a fixed number of steps.

Why it matters

  • Parallel refinement can cut sequential steps vs. autoregressive decode.
  • Models like DiffusionGemma explore non-causal generation.
  • Quality and tooling still maturing relative to autoregressive LLMs.

Section 7 & 8

Production decision guide

01

Profile first: measure TTFT vs TPOT, then decide whether you are prefill- or decode-bound.

02

Enable paged KV and prefix caching before touching model precision.

03

Right-size batch/concurrency to shift along the roofline; watch for the ridge point.

04

Quantize to match the bottleneck: W4A16 decode, FP8/NVFP4 prefill.

05

Adopt optimized attention kernels (FlashAttention / FlashInfer) as the baseline.

06

Consider chunked prefill or disaggregation when p99 latency is hurt by prefill interference.

07

Layer speculative decoding only after the target model is already efficient.

→

Then route with SRouter across heterogeneous replicas for the best cost/latency fit.
