Module 00 — Opening & Foundations

Slide 1 & 2: Why Quantize & The Engineering Trilemma

Memory bandwidth vs compute bottlenecks, and the delicate balance between VRAM, Speed, and Reasoning Fidelity.

Pillar 01

Memory — Frontier Enabler

  • Warehouse collapse: 16-bit weights require 800GB–2TB+ for 405B–1T models. FP8/FP4 fits them onto a single 8-GPU node.
  • Workstation unlock: 70B models shrink from 140GB down to <40GB, running smoothly on 1 GPU.
  • KV Cache space: Leaves headroom for 32k–128k context windows which otherwise outgrow weights.
Key insight: Eliminates inter-node tensor parallel bottlenecks across InfiniBand.
Pillar 02

Speed — Match the Bottleneck

  • Low Batch (Chat/Agents): Memory-bandwidth bound. Weights transfer time dominates. Weight-only W4A16 gives direct speedup.
  • High Batch (Serving): Compute bound. Tensor Cores saturated. Requires native low-bit GEMMs (FP8, NVFP4).
  • Dequant Trap: Naive routing (e.g. LLM.int8) saves VRAM but is slower than FP16 due to dispatch overhead.
Key insight: First diagnose whether your pipeline is memory-bound or compute-bound!
Pillar 03

Economics & TCO

  • 3×–5× Cost Reduction: Slashes energy per token and cloud GPU hosting expense drastically.
  • Faster Cold Starts: Docker container pulls and checkpoint sync times drop in half or more.
  • Edge Democratization: Runs production models on Apple Silicon (MLX), CPUs, and single consumer RTX GPUs.
Key insight: Headline bit-widths lie: always calculate scales & hardware ISA compatibility.

Module 02 — Quantization Strategy & Calibration

Slide 4 & 5: PTQ vs. QAT & The Calibration Trap

Zero-cost PTQ, Parameter-Efficient QAT (PE-QAT), calibration dataset distribution shifts, and why Perplexity lies.

PTQ ~95% Deployments

Post-Training Quantization

Forward pass only over 128–512 calibration samples. Zero backprop, zero gradient compute. Quantizes in 5 to 60 minutes on a single node.

Compute Cost: Near $0 (Minutes)
Sweet Spot: 8-bit & 4-bit (AWQ, GPTQ)
Failure Mode: Unbounded cascades below 4-bit
Modern Fix Recommended for <4-bit

PE-QAT / ZeroQAT

Freeze the base model weights completely; train only LoRA adapters or step-size clipping bounds (<2% parameters) under simulated quantization noise.

Compute Cost: Single developer node (1–4 hours)
Sweet Spot: 2-bit to 3-bit regimes
Advantage: Near full-QAT quality without cluster bills
Full QAT Cluster Compute

Quantization-Aware Training

Retrains or continues pre-training with fake-quantization nodes. Backprop calculates gradients via straight-through estimators (STE).

Compute Cost: Massive (Hundreds of GPU cluster hours)
Sweet Spot: Pre-training from scratch (DeepSeek FP8)
Disadvantage: Cost-prohibitive for standard teams
Trap 1: Generic Calibration Corpus

Calibrating on WikiText-2 or C4 causes brutal domain mismatch. If serving SQL or legal contracts, calibrate on 128–512 domain-specific sequences at 2048–4096 tokens (not short 512 snippets).

Trap 2: Runtime Kernel & Precision Parity

Calibration statistics MUST match your production serving runtime: exact attention backend (Eager vs FlashAttention-2 vs FlashInfer) and compute datatypes (FP16 vs BF16 vs FP8).

Trap 3: Perplexity (PPL) Lies!

Perplexity frequently remains completely stable while strict JSON adherence, multi-hop reasoning, and code syntax break down. Always gate release on task suites (GSM8K, MMLU, JSON schema).

SmoothQuant & Layer Rotations (W4A4)

Slide 8

For W8A8 and W4A4, activations are the primary failure point. SmoothQuant migrates difficulty from activations to weights with an exact mathematical identity.

Y = (X · diag(s)⁻¹) · (diag(s) · W) = X̂ · Ŵ
X̂ (Activations)
Scaled down by s; outliers suppressed
Ŵ (Weights)
Scaled up by s; absorbs difficulty
Balancing factor: α = 0.5 splits quantization difficulty 50/50
QuaRot & SpinQuant: Disperses outliers across all channels via orthogonal rotation matrix R (Cayley SGD), enabling viable W4A4 with <3% perplexity delta!

Module 04 — Modern Floating-Point Formats

Slide 9: FP8, OCP Microscaling (MX), and Blackwell NVFP4

Why exponents beat integer grids at low bits, and the hardware reality check across Hopper, Ada, and Blackwell.

Cloud Standard Ada & Hopper

FP8 (E4M3 vs. E5M2)

Floating-point scales absorb activation outliers natively. Dynamic per-token scaling prevents clipping without retraining.

E4M3 (Range ±448)
1 sign | 4 exponent | 3 mantissa
Inference weights, activations, KV cache
E5M2 (Range ±57,344)
1 sign | 5 exponent | 2 mantissa
Training gradients (prevents underflow)
vLLM flag: --kv-cache-dtype fp8
Open Standard Cross-Vendor

OCP Microscaling (MX)

Block of 32 elements shares a single 8-bit exponent scale (E8M0). Pure power-of-two bit shift arithmetic.

MXFP4 Effective: ~4.25 bpw
MXFP6 Effective: ~6.25 bpw
Applied to BOTH weights AND activations natively.
⚠ Awaiting native accelerator silicon instruction rollouts.
Blackwell Only B100 / B200

NVFP4 Dual Scaling

Raw E2M1 FP4 only spans -6.0 to +6.0. NVIDIA solves saturation via nested two-tier scales:

Outer Scale (FP32):
1 per entire tensor (prevents global saturation)
Inner Scale (E4M3 FP8):
1 per 16 elements (fine local range)
Effective footprint ≈ 4.5 bpw
⚠ Hard requirement: Cannot execute on Hopper (H100) or Ada!

01. THE RISK
Narrow Accumulator

FP8 accumulator has ~13–14 effective bits vs 23 for FP32. Long dot products compound rounding errors, causing training divergence.

02. THE ARCHITECTURE
Fine-Grained Tiling

Activations sliced into [1 × 128] token tiles. Weights blocked into [128 × 128] GEMM tiles to keep reductions short.

03. THE OUTCOME
Zero Quality Loss

671B MoE pre-trained end-to-end with high stability, saving over 50% cluster training memory and millions in training costs.

KV Cache: Size It Right, Then Quantize It

Slide 11

At 32k–128k context lengths, KV cache memory dwarfs the model weights themselves.

KV Memory / Token = 2 × (Layers) × (KV Heads) × (Head Dim) × (Bytes/Elem)
The 8× GQA Capacity Sizing Blunder:

Under Grouped-Query Attention (GQA), modern models (Llama 3, Qwen 2.5) share KV heads across query heads. Llama-3-70B has 64 query heads but only 8 KV heads! Sizing with query heads overstates KV cache by exactly 8×. Always read num_key_value_heads in config.json!

Tier 1: FP8 KV Cache
vLLM --kv-cache-dtype fp8. Halves memory with <0.1% accuracy drop. Double context length instantly.
Tier 2: ~2-bit (KIVI)
Keys per-channel, Values per-token. Recent 32–128 tokens in FP16. Reaches 2-bit with minimal PPL loss.

Slide 12 Edge Shootout

Apple MLX vs. GGUF (llama.cpp)

Two ecosystems for Apple Silicon, CPU & commodity workstations
Apple MLX Fastest Mac Decode
  • • Format: Affine 2/4/8-bit with group size 64.
  • • Standout: Metal kernels fuse dequantization + matmul into single threadgroups without CPU roundtrips.
  • • Performance: Superior token generation (decode) speed on M3/M4.
  • • ⚠ Hardware Trap: Defaults to bfloat16 which is emulated on M1/M2 → causes sluggish prefill at long context!
GGUF / llama.cpp Universal Portability
  • • Format: K-quants & I-quants packaged in a single .gguf file loaded instantly via mmap.
  • • Gold standard: Q4_K_M (~4.85 bpw) promotes sensitive attention matrices to 6-bit.
  • • Extreme limit: I-Matrix calibration enables usable 2–3 bit models (IQ3_XXS).
  • • ⚠ Hardware Reality: CPU fast path uses 8-bit integer SIMD (AVX-512 VNNI / ARM NEON); no native 16-bit integer dot product exists!
Module 06 — Closing & Decision Framework

Slide 13: Decision Flowchart & 5 Production Rules of Thumb

Select your exact format, runtime, and serving backend based on target silicon and concurrency requirements.

Step 1: Choose Target Hardware Tier
BRANCH A — BLACKWELL B100/B200

NVFP4 via TensorRT-LLM

Maximum compute throughput (up to 4× BF16 FLOPS) with dual-level FP32/E4M3 scaling. Slashes inter-node bottlenecks.

Primary: Highest token throughput
BRANCH B — HOPPER / ADA (BATCH > 32)

FP8 (W8A8) via vLLM / SGLang

Compute-bound serving at scale. Native FP8 Tensor Core GEMMs + FP8 KV cache. Zero accuracy degradation on modern models.

Primary: High-concurrency production
BRANCH C — HOPPER / ADA (BATCH 1–16)

AWQ W4A16 (Marlin Kernels)

Memory-bandwidth bound low-latency serving (chat/agents). Fits large models into minimal GPUs with peak memory transfer rates.

Primary: Low latency & VRAM constrained

The 5 Production Rules of Thumb

RULE 01
Balance the Trilemma

Cutting VRAM does not guarantee faster latency. Know whether you are memory-bandwidth or compute bound.

RULE 02
Account for Metadata

Nominal 4-bit is misleading. Always add 10%–20% memory buffer for zero-points, group scales, and runtimes.

RULE 03
In-Domain Calibration

Calibrate with 256+ in-domain texts at 2048–4096 tokens. Never release on PPL alone; test JSON & reasoning tasks.

RULE 04
Verify Hardware ISA

NVFP4 is Blackwell-only. Apple M1/M2 requires FP16 to avoid slow emulated bf16 prefill. Check before promising.

RULE 05
Quantize KV Cache

Enable FP8 KV in vLLM to instantly double context capacity. Size using num_key_value_heads to avoid 8× error.
